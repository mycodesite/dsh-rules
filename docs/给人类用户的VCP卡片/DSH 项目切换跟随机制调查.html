核心结论 Core Finding · 根据当前对话的项目切换方法
1
DSH 的"项目切换跟随"本质是 cwd 驱动的会话级上下文绑定，不是独立切换引擎。对话 = session，项目 = workspace，两者通过 realpath(session.cwd) === workspace.path 绑定。
2
切换对话 = 切换 session：前端 selectWorkspace → openWorkspace → connectWorkspace → sessions.create({workspaceId}) → openSession，session 创建时 cwd = workspace.path 写入不可变的 header.cwd。
3
跟随靠 cwd：所有能力在 agent/pre-step 按 session.header.cwd 重新加载——agent-instructions 加载 AGENTS.md/CLAUDE.md、文件/shell 工具按 cwd 解析、sandbox 按 cwd 设边界、skill 按 cwd 选 roots（缓存键含 cwd 变更即失效）、系统提示 cwd 变量取自 header.cwd。
4
cwd 不可变：切换项目必走新建/打开另一个 session（ApiSessionCwdConflict 阻止原地改 cwd），而非在原对话上改 cwd。
5
两套 scope 须区分：① DSH 源码内置（agent-instructions 加载 AGENTS.md/CLAUDE.md，skill ScopeKey 是 agent preset 维度）；② 插件层（rulebase 的 .dsh/rules、connector/kb/memory 的 scope=project 按 workspaceId 隔离），两者经 cwd === workspace.path 数据对齐。
