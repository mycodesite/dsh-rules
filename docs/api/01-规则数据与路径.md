# 01-规则数据与路径（`src/host/paths.ts`）

规则目录与规则级别的通用解析，供 `RuleStore` 与 `RuleInjector` 复用，不依赖任何 dsh 运行时包。

## 导出

### 类型 `RuleLevel`

```ts
type RuleLevel = 'global' | 'project'
```

规则所属级别：

| 值 | 含义 |
|:--|:--|
| `'global'` | 全局规则，存储于 `<DSH home>/rules`（跟随 `DSH_HOME`，未设置时 `~/.dsh/rules`） |
| `'project'` | 项目规则，存储于 `<cwd>/.dsh/rules` |

### `globalRulesDir()`

```ts
function globalRulesDir(): string
```

返回默认全局规则目录的绝对路径：`<DSH home>/rules`。

DSH home 的解析顺序（与 dsh 官方 `resolveDshHome` 的前两档一致）：

| 优先级 | 来源 | 说明 |
|:--|:--|:--|
| 1 | `$DSH_HOME` | `trim()` 后非空时生效；相对值以 `path.resolve` 绝对化 |
| 2 | `~/.dsh` | 未设置或纯空白时回退（`os.homedir()`） |

官方最高档 `configured` 由装配入口消费宿主 cordis 服务 `dshHomePath` 时覆盖（见 05）。

- 无入参；不读 `ctx`，是纯函数（每次调用现读 `process.env.DSH_HOME`，无缓存）。
- 返回值恒为字符串（不检查目录是否已存在）。
- 装配入口把解析结果（优先宿主服务 `dshHomePath`）注入 `RuleStore` 与 `RuleInjector`；本函数是服务不可用时的回退实现。

### `projectRulesDir(cwd?)`

```ts
function projectRulesDir(cwd?: string): string | undefined
```

返回项目规则目录的绝对路径：`path.join(cwd, '.dsh', 'rules')`。

| 参数 | 类型 | 说明 |
|:--|:--|:--|
| `cwd` | `string \| undefined` | 项目根目录；省略或为空时返回 `undefined` |

- `cwd` 来自 `agent.session.header.cwd ?? process.cwd()`（见注入模块的 cwd 解析）。
- 返回 `undefined` 表示「无项目目录」，调用方应跳过项目级规则。

## 设计要点

- 级别 → 目录的映射集中于此，避免在各处重复拼路径；DSH home 解析（`$DSH_HOME` 优先）同样集中于此。
- 目录仅做「路径拼接」，不在此处做存在性校验；`RuleStore.list` 对不存在目录返回空数组。
