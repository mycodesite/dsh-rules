# 01-规则数据与路径（`src/host/paths.ts`）

规则目录与规则级别的通用解析，供 `RuleStore` 与 `RuleInjector` 复用，不依赖任何 dsh 运行时包。

## 导出

### 类型 `RuleLevel`

```ts
type RuleLevel = 'global' | 'project'
```

规则所属级别：

| 值 | 含义 |
|:--|:--|
| `'global'` | 全局规则，存储于 `~/.dsh/rules` |
| `'project'` | 项目规则，存储于 `<cwd>/.dsh/rules` |

### `globalRulesDir()`

```ts
function globalRulesDir(): string
```

返回默认全局规则目录的绝对路径：`path.join(os.homedir(), '.dsh', 'rules')`。

- 无入参。
- 返回值恒为字符串（不检查目录是否已存在）。
- `RuleStore` 构造时可用 `globalDir` 覆盖此默认值（测试隔离用）。

### `projectRulesDir(cwd?)`

```ts
function projectRulesDir(cwd?: string): string | undefined
```

返回项目规则目录的绝对路径：`path.join(cwd, '.dsh', 'rules')`。

| 参数 | 类型 | 说明 |
|:--|:--|:--|
| `cwd` | `string \| undefined` | 项目根目录；省略或为空时返回 `undefined` |

- `cwd` 来自 `agent.session.header.cwd ?? process.cwd()`（见注入模块的 cwd 解析）。
- 返回 `undefined` 表示「无项目目录」，调用方应跳过项目级规则。

## 设计要点

- 级别 → 目录的映射集中于此，避免在各处重复拼路径。
- 目录仅做「路径拼接」，不在此处做存在性校验；`RuleStore.list` 对不存在目录返回空数组。
