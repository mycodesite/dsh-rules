# 解决方案：dsh插件项目规则未选项目无法保存的修复-001

## 1. 问题描述

dsh 启动后、**未开启任何对话**时，在设置面板「规则」区创建「项目」规则无法保存。

原因：未开启对话 → 没有选定项目 → 没有项目路径（项目 cwd 来自 `agent.session.header.cwd`，没有 agent 就没有 cwd）。

**预期行为**：点击「保存」按钮后，弹出对话框告知用户「当前未选定项目，无法保存，请先选定一个项目」。

## 2. 现状与根因分析

### 2.1 保存链路

```
RuleSection.submitEdit
  → controller.create/save
  → RPC create/save（payload 仅 {level, content} / {level, id, content}，无 cwd）
  → host RulesService.invoke
  → RuleStore.save
```

### 2.2 根因

1. **client 请求从不携带 cwd**：`controller.create/save` 的 payload 没有 `cwd` 字段，host 侧 `asString(p.cwd)` 恒为 `undefined`。
2. **host 有 `process.cwd()` 兜底**：`RuleStore.dirOf` 对 project 级做了 `projectRulesDir(cwd ?? process.cwd())`。无 cwd 时项目规则会写到「dsh 进程工作目录」`<process.cwd()>/.dsh/rules`，而非用户选定的项目；未开对话时更无路径可言。
3. **host 无「当前项目」概念**：项目 cwd 只存在于每个 agent 会话（`agent.session.header.cwd`），`RuleInjector` 已在 `activeAgents` 中跟踪，但没有对外暴露，client 无从判断「是否已选定项目」。

## 3. 解决方案

### 3.1 总体思路

host 侧维护「当前项目 cwd」（最近创建的活跃 agent 的 cwd），新增 RPC 端点 `currentCwd` 供 client 查询；client 在保存项目规则前先查询，未选定项目则弹出对话框并中止；已选定项目时，host 对项目级读写自动解析真实 cwd，杜绝写错目录。

### 3.2 host 改动

1. **`src/host/injector.ts`**：新增 `currentProjectCwd()`——从 `activeAgents` 倒序取第一个非空 cwd；无活跃 agent 或无 cwd 返回 `undefined`。
2. **`src/host/service.ts`**：
   - 新增端点 `currentCwd` → `{ cwd: string | null }`。
   - project 级 `list`/`create`/`save`/`remove` 统一经 `resolveCwd`（client 传入 cwd 优先，缺省用 `injector.currentProjectCwd()`）解析真实 cwd。
   - `create`/`save` 在 project 级无 cwd 时抛明确错误（提示先选定项目）；`list` 无 cwd 返回 `[]`；`remove` 无 cwd 幂等跳过。
   - `currentCwd` 属读操作，不触发注入刷新。

### 3.3 client 改动

1. **`src/client/controller.ts`**：新增 `currentCwd(): Promise<string | null>`，调 `currentCwd` 端点。
2. **`src/client/RuleSection.tsx`**：
   - 项目 tab 下查询并保存 `projectCwd` 状态；为 `null` 时列表区显示「未选定项目」提示（而非「暂无规则」）。
   - `submitEdit` 保存前（项目级）先查询 `currentCwd`，为 `null` 时 `window.alert('当前未选定项目，无法保存项目规则。请先选定一个项目（开启一个项目对话）后再试。')` 并中止。

## 4. 影响与风险

| 项 | 说明 |
|:--|:--|
| 影响范围 | host：`injector.ts`/`service.ts`；client：`controller.ts`/`RuleSection.tsx`；其余不变 |
| 兼容性 | 新增端点不影响既有端点；client 不传 cwd 时由 host 自动解析，向后兼容 |
| 风险点 | 「当前项目」在多个对话并存时取最近活跃对话的 cwd，属合理近似；弹窗用原生 `window.alert`，符合现有「原生 HTML 自绘、不引入 UI 库」约束 |

## 5. 验证方案

1. **单测**：`npm test`（RuleStore 路径解析与读写回归）。
2. **类型检查**：`npm run typecheck`（host + client）。
3. **构建**：`npm run build` 产出 `lib/index.mjs` + `lib/client.js`。
4. **实测**：真实 dsh web profile 启动，未开对话时创建项目规则 → 断言弹出「未选定项目」对话框且不落盘；开启项目对话后 → 规则保存到 `<项目>/.dsh/rules`。
